> 🚫 **R3: 구현한 에이전트는 자기 코드를 리뷰하지 않는다.**

## 절차

1. 변경 범위를 정한다: `git diff --name-only <base>...HEAD`
2. **ct-auditor 가 필요한가** — 하나라도 해당하면 띄운다:
   - `crates/jamulsoe-core/**` 의 변경
   - `crates/jamulsoe-module/**` 중 키·태그·KAT·무결성 HMAC 을 다루는 코드
   - `crates/jamulsoe-ffi/**` 중 컨텍스트 생성·제로화·해제
   - `rust-toolchain.toml`, 릴리스 프로파일, `RUSTFLAGS`, 대상 CPU 기준선
   - "성능 최적화" 커밋 전부
3. 리뷰어를 **한 메시지에서 동시에, 새로** 띄운다:

| 리뷰어 | 보는 것 |
|---|---|
| `rust-reviewer` | `docs/RUST-GUIDE.md §9` — 패닉 경로, 산술, unsafe 근거, 가시성, 문서 |
| `contract-auditor` | C2~C5, I1~I5 — "어떤 계약을 건드리고, 그것을 막는 테스트가 있는가" |
| `ct-auditor` (조건부) | C1 — 소스와 릴리스 어셈블리의 비밀값 경로, ctgrind 결과. **감사 결과를 `docs/audits/` 에 직접 새 파일로 남긴다** |

각 리뷰어에게 전달할 것 — **이것만**:
- 변경된 파일 목록
- 이 변경이 건드린다고 **주장하는** 계약 (감사자는 이 주장을 검증한다)

구현자의 설명·요약은 전달하지 않는다 (`.agents/INDEPENDENCE.md`).

**R1 확인** (`contract-auditor`): 구현 커밋보다 먼저 `TEST:` 커밋이 있고, PR 본문의 그 시점 실패 출력이 기대값 불일치인가.
의심스러우면 테스트 커밋을 체크아웃해 직접 돌려 본다.

## 심각도 — `docs/CODE-REVIEW.md`

| 심각도 | 뜻 | 머지 |
|---|---|---|
| **[P1] 치명** | 계약·불변식 위반, 비밀값 누출(타이밍·사본·로그), 메모리 안전, 패닉 경로, 테스트 무력화, 미검증 `unsafe` | ❌ 차단, 고치고 **재리뷰** |
| **[P2] 높음** | 정확성 위험, 테스트 부족, 규약 위반, 문서와 코드 불일치 | ⚠️ 수정 또는 이슈+기한 |
| **[P3] 제안** | 가독성, 네이밍, 문서 | ✅ 선택 |

**[P1]은 구체적 실패 시나리오를 대야 한다.** 못 대면 [P2]다.
