## 이 검사의 의미

일부러 틀린 구현을 만들어 테스트가 **실패하는지** 본다. 뮤턴트를 켰는데 테스트가 통과하면, 그 테스트는 아무것도 검증하지 않는 것이다.

> **살아남은 뮤턴트 = 테스트의 결함이지 구현 버그가 아니다. 구현을 고치지 말고 테스트를 강화한다.**

대상: `jamulsoe-core` (M1), + `jamulsoe-module` (M2), + `jamulsoe-ffi` (M3).

## 범위

| 언제 | 범위 | 방법 |
|---|---|---|
| PR (`verify.sh`, CI) | **diff 에 걸친 뮤턴트만** | `--diff-base` (CI 는 `JMS_DIFF_BASE`=PR base, 로컬은 `origin/develop` 과의 merge-base) → `cargo mutants --in-diff` |
| 마일스톤 종료 (`verify.sh --milestone`) | 대상 크레이트 **전체** | diff 없이 |

증분은 빠른 피드백일 뿐이다. 한 곳의 변경이 다른 곳의 테스트를 약하게 만들 수 있으므로 종료 판정은 전체로 한다.

## 관측할 수 없는 변이 — 면제

동치 뮤턴트나 Drop 의 제로화처럼 **정상 동작에 흔적이 없는** 변이가 있다. 억지 테스트로 잡은 척하지 않는다.

1. 왜 관측할 수 없는지, 대신 무엇이 확인하는지(예: C4-03 어셈블리 감사)를 정리한다
2. 사람에게 `tests/mutants/exempt.toml` 항목 추가를 요청한다 (사람만 고친다 — `mutant`·`reason`·`approved_by` 필수)
3. "테스트 쓰기 어렵다"는 면제 사유가 아니다

## 이 모듈에서 반드시 죽어야 하는 변이

| 변이 | 잡아야 하는 테스트 |
|---|---|
| 태그 비교가 항상 같음 | GCM open 변조 코퍼스 (I2) |
| open 이 검증 전에 복호화 | 실패 시 in-place 암호문 무변경 (I2) |
| 겹침 검사 제거·경계 off-by-one | 겹침 코퍼스 (C2) |
| 길이 상한·키 길이 검사 제거 | 최대 길이 초과·키 길이 코퍼스 (C2-05, C2-19) |
| 오류 전에 출력 기록 | 센티널 무변경 (I1) |
| 상태 검사 생략 | 오류 상태 서비스 차단 (I3) |
| 키 스케줄 회전 방향·라운드 수 | 정답 벡터 + 오라클 차등 |
| GHASH 길이 블록 바이트 순서 | AAD·평문 길이 조합 벡터 |
| HMAC 긴 키 정규화 생략 | RFC 4231 의 긴 키 케이스 |
