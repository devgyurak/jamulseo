대상: **$ARGUMENTS**

> **R1: 하네스가 먼저, 구현은 나중.** 이 단계를 건너뛰는 것이 가장 흔한 실패 모드다.

## 전제

- ADR 에서 나온 작업이면 그 ADR 의 `방향 확인` 이 채워져 있다. `대기` 면 시작하지 않는다 (①′)

## 절차

1. 대상이 어떤 계약 조항에 속하는지 `docs/CONTRACTS.md` 와 `tests/contracts/registry.json` 에서 확인한다.
2. `harness-engineer` 로 대상에 맞는 것을 만든다:

   | 대상 | 만드는 것 |
   |---|---|
   | 알고리즘 | 정답 벡터 파일 + `SOURCES.md` 기록 + 벡터 러너, 경계 길이 테스트, `jamulsoe-ct` 대상 |
   | GCM open | 위 + 1비트 변조(태그·AAD·암호문) 코퍼스, 실패 시 출력 무변경(I2) 테스트 |
   | 모듈 상태 | 상태 전이 테스트, `fault-injection` 실패 주입 테스트, 동시성 테스트 |
   | C ABI 함수 | `tests/negative/` 코퍼스 + 러너(오류 코드 **와** 센티널 무변경), 퍼징 타깃, C 스모크 |

3. **동시에** `oracle-author` 를 **새로 띄워** 참조 모델을 확장한다 (알고리즘일 때).
   `./scripts/spec-bundle.sh --for oracle-author` 묶음만 열게 한다. 두 에이전트는 서로의 산출물을 보지 않는다.
4. 계약 조항이면 `tests/contracts/registry.json` 의 해당 단계 `test` 에 테스트 이름을 추가한다 (항목·마일스톤·검사 종류는 바꿀 수 없다).
5. 테스트를 실행해 **기대값 불일치로 실패하는지** 확인한다.

## 정답 벡터를 넣을 때

- 원본 파일 그대로, **새 파일로**. 형식 변환이 필요하면 변환 스크립트를 함께 커밋한다
- `tests/vectors/SOURCES.md` **끝에** 한 줄: 파일 / 출처(URL·문서명·판) / 확보일 / 원본 SHA-256
- 판·연도를 확인하지 못했으면 "확인 필요" 라고 쓴다 (R10)

## 종료 조건

- [ ] 테스트가 **실패한다** — 그리고 실패 원인이 `todo!()` 패닉·빌드 오류가 아니라 **기대값 불일치**다
- [ ] 실패 메시지가 무엇이 왜 틀렸는지 설명한다 (벡터 ID·기대값·실제값)
- [ ] `./scripts/lint-gwt.sh` 통과
- [ ] 계약 항목이면 레지스트리에 테스트 이름까지 연결됨
- [ ] 이 테스트를 무력화할 변이(뮤턴트 후보)를 적어 두었다 — ④에서 `./scripts/mutants.sh` 가 확인한다
- [ ] `TEST:` 커밋으로 남기고, 그 시점의 실패 출력을 PR 본문용으로 보관했다. **이 커밋만 `develop` 에 머지하지 않는다** — 같은 브랜치에서 ③ 구현이 이어진다

## 하지 말 것

- 경계 크레이트의 구현을 쓰지 않는다 (시그니처 스텁만)
- 테스트를 초록 상태로 넘기지 않는다
- 기존 벡터·코퍼스 파일을 수정·삭제하거나 끝에 붙이지 않는다 (새 파일로)
