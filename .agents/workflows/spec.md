주제: **$ARGUMENTS**

## 절차

1. **판별한다** — `docs/PLAN.md` 에서 관련 절을 찾는다.
   - 계획서가 이미 정했다 → 그 절을 인용하고 **여기서 끝낸다.** 새 ADR 을 만들지 않는다
   - 표준 원문·GVI·시험기관만 답할 수 있다 → `docs/kcmvp/inquiry-drafts.md` 에 질문 초안을 추가하고,
     영향받는 작업을 `docs/ROADMAP-STATUS.md` 의 "G1 대기" 로 표시하고 **멈춘다** (R10)
   - 우리가 정할 수 있다 → 3으로
2. `docs/CONTRACTS.md` 에서 이 주제가 건드리는 계약(C1~C5, I1~I5)을 식별한다.
3. `spec-author` 서브에이전트로 ADR 초안을 작성한다 (`docs/adr/0000-template.md`).
4. 초안이 나온 **직후** `spec-redteam` 서브에이전트를 **새로 띄워** 반박한다.
   `./scripts/spec-bundle.sh --for spec-redteam` 묶음만 보게 한다. 3과 동시에 띄우지 않는다 (반박할 초안이 필요하다).
5. 반례를 ADR 에 반영하거나 "호출자 계약 위반" / "보장하지 않음" 으로 명시한다.
   반영한 ADR 을 **새 레드팀 세션**으로 한 번 더 반박한다. **최대 2회전** — 그 뒤에도 새 반례가 나오면
   멈추고 사람에게 범위 결정을 묻는다.
6. 새 반례를 `tests/contracts/registry.json` 에 추가할 항목 목록으로 정리한다 (등록은 ② 에서).
7. **멈춘다 (①′).** ADR·반례·남은 질문을 요약해 보고하고, 사람이 ADR 의 `방향 확인` 을 채울 때까지 ② 로 가지 않는다.
   이것은 채택이 아니다 — 기각되면 하네스·구현을 버려야 하는 비용을 앞당겨 줄이는 확인이다.

## 산출물

- `docs/adr/NNNN-<주제>.md` — **상태: 제안** (확정은 사람이 한다)
- 반례 목록, KCMVP 제출물에 반영할 문구 목록

## 하지 말 것

- 코드를 쓰지 않는다. 이 단계는 명세만이다
- 계획서가 정한 것을 다시 결정하지 않는다
- 시험기관 답변·GVI 조항을 추정해 ADR 의 근거로 쓰지 않는다
- `docs/CONTRACTS.md`·`docs/PLAN.md` 를 직접 수정하지 않는다 (R4)
