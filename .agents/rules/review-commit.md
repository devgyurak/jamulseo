# 코드 리뷰 · 커밋

**전문은 `docs/CODE-REVIEW.md` 와 `docs/COMMIT.md` 에만 있다.**
여기에는 자주 틀리는 것만 적는다 — 복제본은 반드시 원본과 어긋난다.

## 자주 틀리는 것

1. **[P1]을 근거 없이 낸다.** 구체적 실패 시나리오(입력·상태 → 잘못된 결과)를 못 대면 [P2]다
2. **심각도를 낮춰서 통과시킨다.** 계약 위반·상수 시간 위반을 [P3]로 내리는 것은 R4 위반이다
3. **"확인하지 못한 것"을 안 쓴다.** 안 쓰면 전부 봤다고 암묵적으로 주장하는 셈이다
4. **`FIX:` 인데 재현 테스트가 없다.** 재현 테스트 없는 수정은 같은 버그를 다시 부른다
5. **`REF:` 인데 동작이 바뀐다.** 판단 기준: *"이 변경 없이 기존 테스트가 전부 통과하는가?"*
6. **`Contracts:` 트레일러를 빠뜨린다.** `ADD:` `FIX:` `REF:` 에 필수다
7. **`Signed-off-by:` 를 빠뜨린다.** 모든 커밋에 필수(DCO). `git commit -s`
8. **보호 파일을 다른 변경과 섞어 커밋한다.** 사람 승인 대상이므로 별도 커밋이어야 한다
9. **원천(`.agents/`)만 고치고 생성물을 안 올린다.** `./scripts/sync-agents.sh` 결과를 같은 커밋에

## 타입 한 줄

`DEL:` 제거 / `TEST:` 테스트·하네스·벡터·코퍼스 / `DOCS:` 문서·ADR·제출물 초안
