# 역할 독립성 — 의존성 검사로는 부족하다

## 왜 절차가 필요한가

`scripts/lint-boundary.sh` 는 `jamulsoe-oracle` 이 경계 크레이트를 의존하지 못하게 막는다.
그러나 **같은 잘못된 해석을 베끼는 데 크레이트 의존은 필요 없다.**
구현을 읽은 에이전트는 그 구조를 손으로 다시 쓴다. 의존성 검사는 `use jamulsoe_core::...` 를 막을 뿐,
*"구현이 키 스케줄 회전을 이렇게 하더라"* 는 지식이 참조 모델에 들어오는 것을 막지 못한다.

암호에서 이 오염은 특히 치명적이다. ARIA 키 스케줄의 회전 방향, GCM 길이 블록의 바이트 순서,
HMAC 의 긴 키 정규화 같은 **표준 해석 실수**는 구현과 오라클이 같이 틀리면 정답 벡터가 없는 경로에서
아무도 모른다.

독립성은 **실행 절차**로 지켜야 한다. 린트는 마지막 그물일 뿐이다.

---

## 독립이 필요한 역할

| 역할 | 보면 안 되는 것 | 왜 |
|---|---|---|
| `oracle-author` | 경계 크레이트 구현 (`crates/jamulsoe-{core,module,ffi}/src/`) | 구현을 본 오라클은 구현의 해석 실수를 복제한다 → 차등 테스트가 무의미 |
| `core-engineer` · `module-engineer` · `ffi-engineer` | 오라클 구현 (`crates/jamulsoe-oracle/src/`) | **반대 방향.** 오라클은 M0, 코어는 M1 에 만들어지므로 실제 위험은 구현자가 차등 테스트를 디버깅하다 오라클을 열어 그 해석을 베끼는 쪽이다 |
| `spec-redteam` | 구현 전부 (`crates/*/src/`) | "구현이 이러니까 괜찮겠지"로 오염되면 명세의 빈틈을 못 본다 |
| `rust-reviewer` · `contract-auditor` · `ct-auditor` | 구현 세션의 **대화 이력** | 같은 사각지대를 두 번 통과시킨다 (R3) |

## 절차 — 네 겹

### 1겹. 새 세션 (대화 이력 차단)

**구현 세션을 끝내고 새 세션을 연다.** 이어서 호출하지 않는다.

| 도구 | 방법 |
|---|---|
| claude-code | 서브에이전트로 **새로** 띄운다. `SendMessage` 로 다른 역할·구현 문맥의 에이전트를 이어 쓰지 않는다 (예외: 같은 리뷰어의 [P1] 재확인) |
| codex | 새 세션으로 해당 서브에이전트·프로필을 연다. `resume` 하지 않는다 |
| opencode | `@oracle-author` 를 새 세션에서 |
| cursor / pi | 새 대화를 열고 `.agents/roles/<이름>.md` 를 첫 메시지로 붙여 넣는다 |

> 구현 요약을 "참고용으로" 전달하는 것도 오염이다. **명세와 diff 범위만 전달한다.**
> 리뷰어에게는 변경 파일 목록과 "건드린다고 주장하는 계약"만 준다. 구현자의 설명은 주지 않는다.

### 2겹. 명세 전용 작업 묶음

```bash
./scripts/spec-bundle.sh --for oracle-author   # 기본 출력: target/spec-bundle/
./scripts/spec-bundle.sh --for spec-redteam
```

계획서·계약·테스트 전략·ADR·공개 헤더·정답 벡터만 모아 별도 디렉터리로 낸다.
오라클 작성자는 **그 디렉터리만 열고** 참조 모델의 **설계**를 한다. 코드를 쓸 때는 `crates/jamulsoe-oracle/` 만 연다.

### 3겹. 도구 수준 경로 차단

`.agents/roles/*.md` 의 `forbid_read:` 가 생성기를 통해 각 도구 정의에 명시된다.
Codex 는 `sandbox_mode`, Claude 는 `tools` 제한으로 **쓰기**를 막지만,
**읽기 경로 제한은 어느 도구도 완전히 강제하지 못한다.** 그래서 1·2겹이 본체다.

### 4겹. 린트 (마지막 그물)

`scripts/lint-boundary.sh` 가 `jamulsoe-oracle` → 경계 크레이트 의존을 차단한다.
**이것은 독립성의 증거가 아니라, 독립성이 깨졌을 때 잡히는 가장 조잡한 경우일 뿐이다.**

### 표준 원문 — 기억이 아니라 원문으로

독립성은 "서로 안 보기"만으로 부족하다. 둘 다 **같은 모델의 기억**으로 S-box·CK 상수·길이 블록 형식을 쓰면 같이 틀린다.

- 재배포 가능한 원문(RFC 5794·4231·2104, FIPS 180-4·198-1, SP 800-38D)은 `docs/standards/` 에 있다 (`SOURCES.md` 에 해시)
- KS X·TTAK 원문은 재배포할 수 없으므로 사람이 `docs/standards/local/`(git 제외)에 두고 해시만 기록한다
- `spec-bundle.sh` 가 둘 다 묶음에 넣는다. 오라클의 상수에는 **출처(문서·절·쪽) 주석**을 단다
- 원문이 없으면 멈추고 보고한다 (R10)

### 모델 다양성

구현과 오라클을 같은 모델이 쓰면 기억 오류가 상관된다. **가능하면 오라클은 다른 계열 모델로** 돌린다
(Codex 어댑터 `.codex/agents/oracle-author.toml`). 같은 계열밖에 없으면 최소한 표준 원문 의존을 지킨다.

## 차등 테스트가 실패했을 때 (구현자 쪽)

구현자는 **실패한 입력, 기대값, 실제값**만 받는다. 오라클 코드를 열지 않는다.
원인은 표준 원문과 정답 벡터로 찾는다. 그래도 모르겠으면 아래 "갈렸을 때"로 간다.

---

## 오라클과 구현이 갈렸을 때

1. **누가 맞는지 에이전트가 단독으로 판단하지 않는다.**
2. 정답 벡터가 그 입력을 덮는지 확인한다. 덮으면 벡터가 판정한다 (벡터 자체는 고치지 않는다).
3. 덮지 않으면 OpenSSL(ARIA-GCM 지원) 과 KISA 참고 소스(확보한 경우)로 **세 번째 의견**을 구한다.
4. 그래도 갈리면 **명세가 모호한 것**이다. 표준 조항을 인용해 사람에게 보고한다.
