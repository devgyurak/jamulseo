## ① SPEC — 명세

### 진입 조건
- 작업이 **계획서에 없는 결정**을 요구한다 (예: value barrier 헬퍼 형태, 비트슬라이스 표현, 레지스트리 형식)
- 또는 **기존 계약을 건드린다** (C1~C5)
- 계획서가 이미 정한 것(알고리즘 구조, API 초안, 오류 코드, CSP 인벤토리, 겹침 규칙 등)은 **다시 결정하지 않는다**
- 순수 리팩터링·계약 무관 버그 수정은 건너뛴다 (버그가 계약 위반이면 건너뛸 수 없다)

### 해석 질문은 ADR 이 아니다
표준·GVI·시험기관만 답할 수 있는 질문(예: "GCM 최대 입력 허용값", "태그 파일의 경계 포함 여부")은
ADR 로 **결정하지 않는다**. `docs/kcmvp/inquiry-drafts.md` 에 질문 초안을 쓰고, 영향받는 작업을 G1 대기로 표시한다.
사람이 초안을 다듬어 실제로 문의하고, 질문과 **답변**을 `docs/kcmvp/inquiries.md` 에 기록한다.
`inquiries.md` 는 사람만 고친다 (`.agents/APPROVAL.md`) — 답변을 에이전트가 지어낼 수 없게.

### 산출물
- `docs/adr/NNNN-<주제>.md` (상태: 제안)
- 계약 레지스트리(`tests/contracts/registry.json`)에 추가할 항목 목록 (있으면)

### ADR 템플릿의 필수 섹션
```
맥락 / 고려한 선택지(최소 3) / 결정 / 근거(표준·논문 포함) / 기각한 것과 이유
건드리는 계약 / 만드는 새 반례 / KCMVP 영향 / 검증 방법 / 되돌리는 비용
```

### `spec-redteam` 운용
> **구현 코드를 읽지 않는다.** 명세만 읽고 "명세를 지켜도 호출자나 시험기관이 놀랄 반례"를 찾는다.

**새 세션으로 띄운다.** 구현 문맥이 섞이면 "구현이 이러니까 괜찮겠지"로 오염된다.
반박은 **최대 2회전**. 2회전 뒤에도 새 반례가 나오면 사람에게 범위 결정을 묻는다.

### 종료 조건
- [ ] 레드팀 반례가 전부 명세에 반영되었거나, 명시적으로 "보장하지 않음"(호출자 계약)으로 기록됨
- [ ] ADR 이 있으면 **①′ 로 넘기고 멈춘다** (아래)
- [ ] 건드리는 계약이 식별됨
- [ ] KCMVP 제출물(보안정책문서·설계서)에 반영해야 할 문구가 식별됨
- [ ] 되돌리는 비용이 평가됨 (G1 이후 ABI 변경, `kcmvp/v1` 이후 변경은 재검증 사유)

## ①′ 방향 확인 — 사람 (ADR 이 있을 때만)

ADR 채택(⑥)은 구현과 리뷰 뒤에 온다. 그때 기각되면 하네스와 구현을 버려야 한다.
그래서 레드팀 반박 직후, ② 로 가기 전에 **사람이 방향만 한 번 확인**한다.

- 에이전트: ADR(제안)·반례·남은 질문을 요약해 보고하고 **멈춘다**
- 사람: ADR 머리말의 `- **방향 확인**: 대기` 를 `이름 날짜` 로 바꾼다 (판정기가 에이전트의 수정을 막는다)
- 이것은 **채택이 아니다.** 상태는 `제안` 그대로이고, 채택은 ⑥ 에서 증거를 보고 한다

## ② HARNESS — 하네스 먼저 (R1)

### **이 단계를 건너뛰는 것이 가장 흔한 실패 모드다.**

"정답 벡터 하나 맞추면 끝"이라는 판단을 하지 않는다.
정답 벡터는 **정상 경로 하나**를 확인할 뿐이다. 사고는 실패 경로·경계값·타이밍에서 난다.

### 진입 조건
- ADR 에서 나온 작업이면 그 ADR 의 `방향 확인` 이 채워져 있다 (`대기` 면 시작하지 않는다)

### 하네스와 구현은 같은 PR

```
작업 브랜치:  TEST: 커밋 (빨강)  →  ADD/FIX: 커밋 (초록)  →  PR  →  CI 는 PR 끝(초록)에서 판정  →  main
```

- 구현을 겨냥한 실패 테스트를 **따로 `develop` 에 머지하지 않는다.** `develop` 이 빨개지면 이후의 모든 PR 이 게이트 6·7 에서 막힌다
- R1 의 증거는 **커밋 순서**와 **테스트 커밋 시점의 실패 출력**이다. 실패 출력(기대값 불일치)을 PR 본문에 붙이고, 리뷰어가 확인한다
- 작업 브랜치에는 빨간 테스트 커밋을 push 할 수 있다 — `pre-push` 는 작업 브랜치에서 정적 게이트(0~5)만, `develop`·`main`·`kcmvp/*` 에서 `--fast` 전체를 돈다
- 예외 — 경계 밖 하네스 자체(오라클, `jamulsoe-ct`, 러너)는 스스로 초록이어야 하며 따로 머지할 수 있다 (M0)

### 산출물

| 대상 | 산출물 |
|---|---|
| 모든 변경 | 실패하는 GWT 단위·통합 테스트 |
| 알고리즘 (core) | 정답 벡터 러너 + 벡터 파일(`tests/vectors/`, 출처 기록) + 오라클 차등 + 상수 시간 타깃(`jamulsoe-ct`) |
| 모듈 (module) | 상태 전이 테스트, 실패 주입(`fault-injection` feature) 테스트, 동시성 테스트 |
| C ABI (ffi) | 실패 케이스 코퍼스(`tests/negative/`) + 러너, 퍼징 타깃, C 하네스(`tests/c/`) |
| 계약 관련 | `tests/contracts/registry.json` 항목과 연결된 테스트 |
| 새 검사기 | 그 검사기를 무력화하는 뮤턴트 후보(어떤 변이에 실패해야 하는지) |

### 정답 벡터 추가 규칙
- 벡터 파일은 **원본 그대로** 넣는다. 변환이 필요하면 변환 스크립트를 함께 커밋한다
- `tests/vectors/SOURCES.md` 에 출처 URL·문서명·판, 확보 날짜, 원본 SHA-256 을 기록한다
- 벡터 데이터는 **새 파일 추가만** 가능하다 (기존 파일 끝에 붙이는 것도 안 된다). `SOURCES.md` 는 끝에 행 추가만
- 벡터와 구현이 다르면 **벡터를 의심하기 전에 구현을 의심한다.** 그래도 벡터가 틀렸다고 보이면 근거를 대고 멈춘다

### `oracle-author` 운용
> **경계 크레이트 구현을 읽지 않는다.** 표준 원문(`docs/standards/`)·계획서만 보고 독립적으로 참조 모델을 작성한다.
> 상수(S-box, CK, 초기값)는 원문에서 옮기고 출처(문서·절·쪽)를 주석으로 남긴다. 기억으로 쓰지 않는다.
> 반대 방향도 막는다: **구현 엔지니어는 오라클 구현을 읽지 않는다** (`.agents/INDEPENDENCE.md`).

참조 모델은 느리고 단순해도 된다 (테이블 S-box, 비트 단위 GF(2^128) 곱셈 등). 상수 시간일 필요가 없다 — 경계 밖이다.
`scripts/lint-boundary.sh` 가 `jamulsoe-oracle` 의 경계 크레이트 의존을 기계적으로 차단한다.
해석이 구현과 다르면 **명세가 모호한 것**이고, 사람이 결정한다.

### 종료 조건
- [ ] 테스트 커밋 시점에서 테스트가 **실패한다** (초록이면 테스트가 아무것도 검증하지 않는 것)
- [ ] 실패가 빌드 오류가 아니라 **대상 동작의 반례**임을 확인했다 (`todo!()` 스텁의 패닉은 실패 증거가 아니다 — 기대값 불일치로 실패해야 한다)
- [ ] 그 실패 출력을 PR 본문에 붙일 수 있게 남겼다 (③ 이 같은 브랜치에서 이어 받는다)
- [ ] 실패 메시지가 무엇이 왜 틀렸는지 설명한다
- [ ] GWT 네이밍 검사 통과
- [ ] 계약 항목이면 레지스트리에 테스트 이름까지 연결했다

> | 시점 | 명령 | 의미 |
> |---|---|---|
> | push (`pre-push`) | 작업 브랜치: 정적 게이트 0~5 / `develop`·`main`·`kcmvp/*`: `verify.sh --fast` | 작업 브랜치에는 빨간 테스트 커밋(R1)을 올릴 수 있다. develop 에는 깨진 것을 올리지 않는다 |
> | 머지 (CI) | `JMS_REQUIRE_ALL=1 verify.sh` | 현재 마일스톤의 필수 게이트 전부 |
> | 마일스톤 종료 | 기준 장비에서 `JMS_REQUIRE_ALL=1 JMS_CT_BASELINE_HOST=1 verify.sh --milestone Mx` + 사람 확인 | 해당 마일스톤의 종료 조건 (뮤테이션 전체, dudect 포함) |
>
> 어느 시점에서도 "미적용"이나 "실행 불가"를 통과로 세지 않는다. `--no-verify` 로 우회하지 않는다.

### 실패 시 대응

| 게이트 | 올바른 대응 | **하면 안 되는 것** |
|---|---|---|
| clippy | 코드를 고친다 | `#[allow(...)]` 추가 |
| 커버리지 | 테스트를 추가한다 | 임계값 낮추기, assert 없는 테스트 |
| 정답 벡터 | 구현을 고친다 | 벡터 수정·삭제 (판정기가 막는다) |
| 계약 역방향 | 누락 테스트를 쓴다 | 레지스트리에서 항목 삭제·`milestone` 미루기 |
| 뮤테이션 | **테스트를 강화한다** | 구현을 고치기, 억지 테스트로 관측 불가능한 변이를 잡은 척하기 (→ 사람에게 면제 요청) |
| 상수 시간 | 구현을 고치고 어셈블리를 확인한다 | 반복 실행해 통과하길 기대, 임계 완화 |
| ABI | 의도한 변경이면 사람 승인 요청 | `exports.txt`·헤더를 맞춰 고치기 |
| 퍼징 | 재현 입력을 코퍼스에 고정하고 고친다 | 크래시 입력을 버리기 |
