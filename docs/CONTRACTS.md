# 계약 — C1~C5, I1~I5

> **이 문서는 사람만 고친다** (`AGENTS.md` R4, `.agents/APPROVAL.md`).
> 내용은 `docs/PLAN.md`(2026-10-02 동결본)의 규칙을 **조항 ID 로 쪼개 옮긴 것**이다. 계획서와 다르면 계획서가 이긴다 —
> 차이를 발견하면 이 문서를 고치는 ADR 을 제안한다.
> 각 조항은 `tests/contracts/registry.json` 의 항목과 1:1 로 연결된다 (`./scripts/contract-check.sh`).

계약은 두 부분으로 읽는다: **모듈이 약속하는 것**과 **약속하지 않는 것(호출자 계약·한계)**.
약속하지 않는 것을 적지 않으면, 보안정책문서가 코드보다 많이 약속하게 된다.

## C1 상수 시간

**정의** (계획서 §상수 시간의 정의): 검증 대상 CPU와 고정된 컴파일러에서, 비밀값에 따라 제어 흐름과 메모리 접근 주소가
달라지지 않고, 비밀값에 의존하는 가변 지연 명령을 쓰지 않는다.

**비밀값**: 키, ARIA 라운드 키, W0~W3, GHASH 키 H, 키스트림·카운터 블록, 평문, 계산된 태그(비교 전),
HMAC 키·정규화 값·ipad/opad 상태.
**공개값**: 모든 길이, IV, AAD, 암호문, 입력 태그, 모듈 상태, 오류 코드의 종류.

| ID | 조항 | 마일스톤 |
|---|---|---|
| C1-01 | ARIA S-box 4종은 테이블 조회 없이 회로(비트슬라이스)로 계산한다 | M1 |
| C1-02 | GHASH 곱셈은 테이블 없이 정수 곱셈 캐리리스 곱셈으로 계산한다 | M1 |
| C1-03 | GCM 태그 비교는 비교 결과와 무관하게 16바이트 전부를 같은 경로로 처리한다 | M1 |
| C1-04 | ARIA 키 스케줄·라운드에 비밀값 의존 분기·인덱싱이 없다 | M1 |
| C1-05 | HMAC 키 처리(64바이트 초과 정규화 여부를 제외한 패딩·XOR)에 비밀값 의존 분기가 없다. 정규화 여부는 **키 길이(공개값)** 로만 정한다 | M1 |
| C1-06 | 비밀값 마스크·선택 연산은 value barrier 를 거친다 | M1 |
| C1-07 | 비밀값을 Valgrind 미정의로 표시한 실행(ctgrind)에서 비밀값 의존 분기·주소가 없다. CI 차단 게이트다. M3 부터는 `libjamulsoe.so` 를 C ABI 로 거치는 대상을 포함한다 | M1 · M3(.so 경유) |
| C1-08 | 기준 장비(`build/baseline.toml` 의 `ct_host_model`)에서 dudect 통계 검사의 t 절댓값이 `DUDECT_T_MAX` 이하이고, 결과를 `docs/audits/` 에 남긴다. 마일스톤 종료 조건이다 | M1 · M3(.so 경유) |
| C1-09 | 비밀값 경로의 릴리스 어셈블리를 감사하고 결과를 `docs/audits/` 에 남긴다. 툴체인·감사 범위 코드가 바뀌면 다시 감사한다 | M1 |

**약속하지 않는 것**
- 검증 대상 CPU 기준선·고정 툴체인 **밖**의 환경
- x86_64 64비트 정수 곱셈이 입력과 무관하게 같은 시간에 끝난다는 **가정** — 보안정책문서에 가정으로 명시한다
- 공개값(길이 등)에 의존하는 실행 시간 차이
- 도구 통과는 증명이 아니다 (회귀 탐지). dudect 는 공유 CI 러너가 아니라 기준 장비에서만 판정한다 (CPU 가 C1 의 "검증 대상 CPU" 여야 하므로)

## C2 C ABI

| ID | 조항 | 마일스톤 |
|---|---|---|
| C2-01 | **오류 시 무변경 (I1)**: v1에서 발생 가능한 모든 오류에서 출력 버퍼와 컨텍스트는 바뀌지 않는다. 예외: `JMS_ERR_SELFTEST` 의 상태 전이, 생성 함수의 `*out = NULL` | M3 |
| C2-02 | 필수 포인터(컨텍스트, IV, 태그, 다이제스트, `**out`)가 NULL 이면 `JMS_ERR_PARAM` | M3 |
| C2-03 | 생성 함수는 진입 즉시 `*out = NULL`, 완전 초기화한 경우에만 핸들을 기록한다 | M3 |
| C2-04 | (포인터, 길이) 쌍: 길이 0 이면 NULL 허용, 길이 > 0 인데 NULL 이면 `JMS_ERR_PARAM`. NULL 로부터 슬라이스를 만들지 않는다 | M3 |
| C2-05 | GCM 평문·암호문·AAD 는 진입 시 `JMS_GCM_MAX_TEXT_BYTES`·`JMS_GCM_MAX_AAD_BYTES` 로 먼저 검사한다 (값은 G1 확정) | M3 |
| C2-06 | SHA-256 누적 입력이 2^61 − 1 바이트를 넘으면 `JMS_ERR_PARAM`, 컨텍스트는 바뀌지 않는다 | M3 |
| C2-07 | HMAC 메시지 상한은 SHA-256 상한 − 64 바이트, 키도 SHA-256 상한 이하. 64바이트 초과 키는 SHA-256 으로 정규화 | M1 |
| C2-08 | 길이×8, 블록 수, offset + len 계산은 전부 checked arithmetic | M1 |
| C2-09 | 가변 길이 출력 용량이 부족하면 `JMS_ERR_BUFFER` | M3 |
| C2-10 | 허용하는 겹침은 GCM `pt == ct` 완전 일치 하나. 입력·출력, 출력·출력(예: `ct`·`tag`)의 부분·완전 겹침은 `JMS_ERR_PARAM`. 입력끼리의 겹침은 허용하되 그 입력이 출력이기도 하면 거부. in-place 에서 AAD·IV·태그가 공유 버퍼와 겹치면 거부 | M3 |
| C2-11 | 겹침 판정은 주소 정수와 checked arithmetic 으로 하고, 길이 0 구간은 어떤 구간과도 겹치지 않는다 | M3 |
| C2-12 | `jms_aead` 는 사용 가능 → 제로화됨, `jms_sha256_ctx` 는 사용 가능 → final 됨. 이후 호출은 `JMS_ERR_CTX_STATE`, 해제만 가능 | M3 |
| C2-13 | `*_free(NULL)` 은 아무 동작도 하지 않는다 | M3 |
| C2-14 | **인증 전 평문 없음 (I2)**: open 은 태그를 먼저 계산·상수 시간 비교하고, 통과할 때만 출력에 쓴다. 실패 시 in-place 에서도 암호문이 그대로 남는다 | M1(core) · M3(ABI) |
| C2-15 | 컨텍스트 할당 실패 시 `JMS_ERR_NOMEM`, `*out == NULL`, CSP 잔존 없음, 모듈 상태 불변 | M3 |
| C2-16 | 어떤 함수도 패닉을 밖으로 내보내지 않는다. 릴리스는 `panic = "abort"`, FFI 경로에 패닉 경로가 없다 | M3 |
| C2-17 | 오류 코드 집합은 계획서 표가 전부다. `JMS_ERR_INTERNAL` 은 예약 코드로 v1 에 발생 경로가 없다 | M3 |
| C2-18 | `jms_version` 은 정적 문자열 포인터를 돌려주고 모든 상태에서 호출 가능하다 | M3 |
| C2-19 | 허용되지 않는 ARIA 키 길이(16·24·32 바이트 밖)는 `JMS_ERR_PARAM` 이다 (계획서 §오류 코드). core 는 같은 조건을 오류로 돌려준다 | M1(core) · M3(ABI) |
| C2-20 | HMAC 키가 KCMVP 보안강도 기준의 하한보다 짧으면 `JMS_ERR_PARAM` 이다. 하한 값은 GVI 확인 후 정한다 (inquiries.md Q12, G1). RFC 4231 테스트 케이스 2 의 4바이트 키("Jefe")와 충돌하므로, 그 벡터를 core 수준에서만 돌릴지 Q12 답변 때 함께 정한다 | M3 |

**약속하지 않는 것 (호출자 계약 위반)**
- 댄글링 포인터, 접근 불가능한 주소, 실제와 다른 길이, 정렬되지 않은 타입 포인터
- 이중 해제, 해제된 핸들 사용, 한 컨텍스트의 다중 스레드 동시 사용
- 캐스팅으로 잘못된 크기의 IV·태그 구조체 포인터를 넘기는 것
- 같은 키·IV 재사용 (사용자 안내서에 SP 800-38D 결정적 구성과 키당 최대 호출 횟수를 명시한다)
- allocator 자체의 abort, OS OOM killer

## C3 모듈 상태·자가시험

상태: **미초기화 → 자가시험 → 승인 동작 | 오류**. (계획서 그림 "모듈 상태 전이 · 4개 상태")

| ID | 조항 | 마일스톤 |
|---|---|---|
| C3-01 | 적재 직후 상태는 미초기화다 | M2 |
| C3-02 | **상태 밖 출력 없음 (I3)**: 암호 서비스는 승인 동작 상태에서만 동작한다. 미초기화·오류 상태에서는 `JMS_ERR_STATE` | M2 |
| C3-03 | 상태 조회, 버전 조회, 제로화, 해제는 오류 상태를 포함한 모든 상태에서 허용된다 | M2 |
| C3-04 | 암호 서비스는 "read lock 획득 → 상태 확인 → 연산" 순서를 지킨다 | M2 |
| C3-05 | `jms_init`: 미초기화면 write lock 을 잡고 자가시험 후 승인 동작 또는 오류로. 승인 동작이면 `JMS_OK`(멱등), 오류면 `JMS_ERR_STATE` | M2 |
| C3-06 | `jms_init` 동시 호출 시 나중 호출은 대기했다가 먼저 끝난 결과에 C3-05 를 적용한다 | M2 |
| C3-07 | `jms_selftest` 는 승인 동작 상태에서만 허용된다. 수행 중 다른 스레드의 암호 서비스는 대기했다가 결과 상태에 따라 실행되거나 `JMS_ERR_STATE` | M2 |
| C3-08 | 자가시험 실패 시 모듈은 오류 상태로 전이하고 `JMS_ERR_SELFTEST` 를 돌려준다 | M2 |
| C3-09 | 자가시험·무결성 시험은 공개 C ABI 를 재진입하지 않고, 서비스가 쓰는 것과 **같은 내부 알고리즘 함수**를 직접 호출한다 | M2 |
| C3-10 | `jms_status` 는 잠금 없이 atomic 만 읽어 자가시험 중에도 즉시 응답한다 | M2 |
| C3-11 | 오류 상태에서 자가시험으로 돌아가는 경로는 없다. 복구는 모듈 재적재뿐이다 | M2 |
| C3-12 | 소프트웨어 무결성 시험(로드 시 HMAC-SHA-256)이 실패하면 오류 상태로 간다 | M2 |
| C3-13 | 자가시험·할당 실패 주입 경로는 검증 바이너리에 존재하지 않는다 (`fault-injection` feature) | M2 |
| C3-14 | 자가시험 KAT 대상: ARIA, ARIA-GCM, SHA-256, HMAC-SHA-256. `jms_selftest` 는 전부 재수행 | M2 |

**약속하지 않는 것 / G1 대기**
- KAT 의 자가시험 분류(조건부) — GVI Part 1 해석 확인 대기
- 오류 전이 시 이미 존재하는 AEAD 컨텍스트 CSP 의 즉시 제로화 — 시험기관 답변 대기. 현재 계약은 "암호 서비스 차단 + 호출자의 zeroize/free 허용"
- C ABI 래퍼·상태 검사·잠금 자체는 KAT 범위가 아니다 (ABI·실패 케이스 테스트가 담당)

## C4 CSP 수명

### 인벤토리 (계획서 §CSP 인벤토리)

| ID | 대상 | 생성 | 보관 | 파기 | 마일스톤 |
|---|---|---|---|---|---|
| CSP-01 | ARIA 입력 키의 모듈 내 사본과 키 스케줄 중간값(W0~W3) | `jms_aria_gcm_new` | 키 확장 중 스택 | 키 확장 직후 | M1(core) · M3 |
| CSP-02 | ARIA 암호화 라운드 키 | `jms_aria_gcm_new` | `jms_aead` 컨텍스트 | `jms_aead_zeroize`, `jms_aead_free` | M3 |
| CSP-03 | GHASH 키 H | `jms_aria_gcm_new` | `jms_aead` 컨텍스트 | `jms_aead_zeroize`, `jms_aead_free` | M3 |
| CSP-04 | GCM 키스트림·카운터 임시값 | seal/open | 스택 | 함수 반환 전 | M1 |
| CSP-05 | HMAC 키, 64바이트 초과 키의 정규화 값, ipad/opad 파생 상태 | `jms_hmac_sha256` | 스택 | 함수 반환 전 | M1 |

GCM 은 암호화 방향만 쓰므로 컨텍스트에 복호 라운드 키를 두지 않는다.
무결성 시험용 고정 HMAC 키의 CSP 해당 여부는 **G1 대기**.

### 조항

| ID | 조항 | 마일스톤 |
|---|---|---|
| C4-01 | **CSP 사본 없음 (I4)**: 인벤토리 밖의 비밀값 사본을 만들지 않고, 인벤토리의 파기 시점에 지운다 | M1 · M3 |
| C4-02 | 비밀값 타입은 `Copy`/`Clone`/`Debug` 를 구현하지 않는다 | M1 |
| C4-03 | 제로화는 `write_volatile` + `compiler_fence` 이고, 릴리스 어셈블리에 남아 있음을 확인한다 | M1 |
| C4-04 | 키 스케줄 함수는 배열을 값으로 돌려주지 않고 `&mut` 출력 인자를 받는다 | M1 |
| C4-05 | AEAD 컨텍스트는 메모리를 먼저 확보한 뒤 라운드 키와 H 를 최종 위치에 직접 계산한다. 스택에서 완성한 값을 `ptr::write` 로 옮기지 않는다 | M3 |
| C4-06 | free 경로는 `zeroize → drop 이 필요한 필드 처리 → 같은 Layout 으로 dealloc` 순서다 | M3 |
| C4-07 | 키는 메모리에만 있고 디스크·로그·오류 메시지에 쓰지 않는다 | M1 |
| C4-08 | 제로화는 컨텍스트 단위다. 모듈 전체 제로화는 두지 않는다 (시험기관 요구 시 레지스트리 추가 — G1) | M3 |

**약속하지 않는 것**: 레지스터와 컴파일러가 만든 스택 사본(spill)은 완전히 통제할 수 없다. 보안정책문서에 한계로 명시한다.
