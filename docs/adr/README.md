# ADR (Architecture Decision Record)

> ⚠️ **채택된 ADR 은 사람 승인 없이 수정할 수 없습니다 (AGENTS.md R4).**
> 훅이 편집을 차단합니다. 바꿔야 하면 **새 ADR 로 대체(supersede)** 하세요.

## 언제 쓰는가

계획서(`docs/PLAN.md`)가 정하지 않은 것 중 **우리가 정할 수 있는 것**만 ADR 로 쓴다.

| 질문의 종류 | 어디로 |
|---|---|
| 계획서가 이미 정했다 | ADR 없음. 계획서 절을 인용 |
| 우리가 정할 수 있다 (구현 설계) | **ADR** |
| 표준 원문·GVI·시험기관만 답할 수 있다 | `docs/kcmvp/inquiry-drafts.md` → 사람이 문의 → `inquiries.md` |

## 번호 규칙

`NNNN-<kebab-case-주제>.md`, `0001` 부터. `0000-template.md` 는 템플릿이다.

## 상태

정규 형식 한 줄만 인정한다 (`scripts/hooks/adr_status.py`):

```
- **상태**: 제안
```

| 상태 | 뜻 |
|---|---|
| `제안` | 에이전트가 작성 가능. 아직 구속력 없음 |
| `채택` | **사람이 승인함.** 구속력 있음. 수정 불가 |
| `대체됨(→ADR-XXXX)` | 다른 ADR 로 교체됨 |
| `기각` | 검토했으나 채택하지 않음. **왜 기각했는지가 가치다 — 지우지 않는다** |

## 방향 확인 (①′)

채택은 구현·리뷰 뒤(⑥)에 온다. 그 사이 기각되면 하네스와 구현을 버려야 하므로, 레드팀 반박 직후 사람이
`- **방향 확인**: 대기` 를 `이름 날짜` 로 바꿔 방향만 먼저 확인한다. 채택이 아니다. 이 필드가 `대기` 면 ② 로 가지 않는다.

## 에이전트의 권한

- ✅ `제안` 상태 ADR 작성·수정(방향 확인은 `대기` 로), 레드팀 반박 반영, 대응 테스트 작성(실패 상태로)
- ❌ `채택`·`대체됨`·`기각` 으로 전환, 그 상태인 ADR 수정(기각을 제안으로 되돌리기 포함), ADR 삭제, `방향 확인` 채우기
