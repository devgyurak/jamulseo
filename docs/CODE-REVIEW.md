# 코드 리뷰 규약

워크플로우 ⑤ REVIEW 단계. 대상: `rust-reviewer`, `contract-auditor`, `ct-auditor`, 사람 리뷰어 전부.

> **표기**: 심각도는 항상 대괄호 `[P1]` `[P2]` `[P3]`. 마일스톤은 `M1`, 게이트는 `G1`.

---

## 1. 전제 — 누가 리뷰하는가

> 🚫 **구현한 에이전트·세션은 자기 코드를 리뷰하지 않는다 (AGENTS.md R3).**

| 리뷰어 | 보는 것 | 보지 않는 것 |
|---|---|---|
| `rust-reviewer` | 패닉 경로·산술·unsafe 근거·의존·문서 (`docs/RUST-GUIDE.md §9`) | 계약의 판정 |
| `contract-auditor` | C2~C5, I1~I5 (`docs/CONTRACTS.md`) | 코드 스타일 |
| `ct-auditor` | C1 — 소스·릴리스 어셈블리의 비밀값 경로 | 기능 정확성 |
| 사람 | 계약·ADR·공개 인터페이스·툴체인·게이트 변경 승인, 설계 방향 | — |

에이전트 리뷰는 **병렬로** 돌린다. 서로의 결과를 보지 않는다.

---

## 2. 심각도

| 심각도 | 뜻 | 머지 |
|---|---|---|
| **[P1]** 치명 | 고치고 **재리뷰** | ❌ 차단 |
| **[P2]** 높음 | 머지 전 수정, 또는 **이슈 + 기한 + 작성자 동의** | ⚠️ 조건부 |
| **[P3]** 제안 | 반영하지 않아도 된다 | ✅ |

### [P1] — 다음 중 하나라도

| 유형 | 예 |
|---|---|
| **계약·불변식 위반** | 출력을 쓴 뒤 실패하는 검사(I1), 검증 전 복호화(I2), lock 없이 상태 확인(I3), 인벤토리 밖 비밀값 사본(I4), `exports.txt` 밖 export(I5) |
| **비밀값 누출** | 비밀값 의존 분기·인덱싱이 **어셈블리에** 있음, 사라진 제로화, 비밀값 로그·Debug |
| **메모리 안전** | 검사 전 슬라이스 생성, NULL 슬라이스, 다른 allocation 간 포인터 산술, 이중 해제 경로, `// SAFETY:` 와 불일치 |
| **패닉 경로** | 경계 안 `unwrap`·인덱싱·overflow — `panic = "abort"` 라 호스트가 죽는다 |
| **경계 위반** | 경계 크레이트의 외부 의존, ffi → core 직접 호출, 두 번째 구현 경로, 비승인 알고리즘 |
| **테스트 무력화** | 테스트·정답 벡터·코퍼스를 고쳐서 통과, `#[ignore]` 테스트를 계약에 연결, 임계값 하향, 레지스트리 항목 삭제·마일스톤 미루기, 억지 테스트로 관측 불가능한 뮤턴트를 잡은 척 |
| **판정 경로 우회** | 셸로 보호 경로 수정, 새 스크립트로 권한 우회, `--no-verify`, 승인자 아닌 `Approved-by:` |
| **과장된 주장** | 문서·주석에 "검증됨/인증됨", 보안정책문서 초안이 코드보다 많이 약속 |

**[P1] 은 구체적 실패 시나리오를 댄다.** "위험해 보인다"는 [P1] 이 아니다.

```
[P1] crates/jamulsoe-ffi/src/gcm.rs:88
유형: contract
계약/불변식: C2-01 (I1), C2-10
실패 시나리오:
  1. ct 버퍼를 0xA5 로 채우고, tag 포인터를 ct + 8 로 준다 (출력·출력 부분 겹침)
  2. 이 코드는 ct 를 쓴 뒤에 겹침을 검사한다
  → JMS_ERR_PARAM 을 돌려주지만 ct[0..pt_len] 이 이미 바뀌어 있다 (I1 위반)
막는 테스트: tests/negative/overlap/ct_tag_partial.json (현재 없음 — 추가 필요)
수정안: 겹침 검사를 진입점 4단계로 옮기고, 슬라이스 생성과 출력 기록을 그 뒤로
```

### [P2]

| 유형 | 예 |
|---|---|
| 정확성 위험 (계약 위반 아님) | 경계값 미처리, 오류 매핑 모호 |
| **테스트 부족** | 새 분기에 테스트 없음, 오류 테스트가 무변경을 안 봄, 레지스트리 미연결, 살아남을 변이 |
| 규약 위반 | `// SAFETY:` 빈약, `Ordering` 근거 없음, `pub` 문서 누락 |
| 문서 불일치 | 헤더 주석·`docs/kcmvp/` 초안과 코드가 다름 (과장이 아닌 경우) |
| 출처 누락 | 외부 자료를 참고했는데 `docs/provenance.md` 미기록 |

### [P3]

가독성, 네이밍, 중복 제거, 주석 보강, 테스트 이름 개선. **강요하지 않는다.**

## 3. 심각도 인플레이션·디플레이션 방지

| 하지 말 것 | 왜 |
|---|---|
| 스타일 선호를 [P1]·[P2] 로 | [P1] 이 흔해지면 아무도 믿지 않는다 |
| 계약·상수 시간 위반을 [P3] 로 | 통과시키려고 낮추는 것은 **R4 위반** |
| 근거 없는 [P1] | 실패 시나리오를 못 대면 [P2] |
| "혹시 모르니 [P2]" | 모르면 **질문**한다 |

리뷰어는 계약을 완화해서 통과시키지 않는다. 계약이 틀렸다고 판단하면 ADR 을 제안하고 멈춘다.


## 5. 승인 조건과 재확인

| 상태 | 조건 |
|---|---|
| **승인** | [P1] 0 · [P2] 해소 또는 합의된 유예 · CI `verify.sh` 통과 |
| **조건부 승인** | [P1] 0 · [P2] 에 이슈 번호와 기한 |
| **변경 요청** | [P1] 1건 이상 |

[P1] 을 고친 뒤에는 **④ VERIFY 를 다시 통과**시키고, **같은 리뷰어가 재확인**한다.
재확인 범위는 수정 diff 와 그 [P1] 이다. 새 [P1] 이 나오면 반복하되 **두 번째 반복부터 사람에게 알린다.**

## 6. 리뷰 결과 요약 형식

```
## 리뷰 요약

| 심각도 | 건수 |
|---|---|
| [P1] | 0 |
| [P2] | 2 |
| [P3] | 3 |

판정: 조건부 승인

확인한 것:
- C2-01·C2-10: 진입점 검사 순서, 겹침 코퍼스 12건 대조
- C4-05: 할당 후 키 스케줄 직접 계산

확인하지 못한 것:
- ASan: macOS 라 실행 불가 — CI 결과 대기
- 릴리스 어셈블리 (ct-auditor 범위)
```

**"확인하지 못한 것"을 쓰는 것이 이 형식의 핵심이다.**

## 7. 자동 리뷰와 사람 리뷰의 경계

| 기계가 하는 것 | 사람이 하는 것 |
|---|---|
| `./scripts/verify.sh` 게이트 | 계약·ADR·공개 인터페이스·툴체인 변경 승인 (R4) |
| 린트, 커버리지, 뮤테이션, CT 회귀, ABI | 임계값 변경 승인 |
| 계약 레지스트리 역방향 검사 | **계약 자체가 옳은가**, 시험기관 해석 |
| 에이전트 교차 리뷰 | 설계 방향, 트레이드오프 수용 |

게이트가 전부 초록이어도 **[P1]이 있으면 머지하지 않는다.**
리뷰에서 새 실패 유형을 발견하면 **게이트로 승격**한다 (린트·코퍼스·레지스트리·뮤턴트).
